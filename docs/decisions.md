# Decisions

ADR-lite. One line per architectural choice, newest last. A line lands in the
same commit as the change it describes.

Format: `YYYY-MM-DD — decision — because`

---

2026-09-27 — mainBrain is a generator plus a library, not a template repository to fork — a fork copies the state of one day and never hears about the next improvement; a generator renders the newest skeleton every time, and the manifest it leaves behind is what lets improvements flow back.
2026-09-27 — One skeleton per repo kind (ops, site, functions, app, lib), rendered with `{{PLACEHOLDERS}}` from an answers file — the questionnaire is the interface and the answers file is its record; a project can be re-rendered from it, which is what `upstream.py` relies on.
2026-09-27 — The stack is Astro + Tailwind on Cloudflare Workers for the site, Firebase Cloud Functions v2 + Firestore for the back end, Vite + React on Cloudflare Workers for the app, plain TypeScript for a library — proven on a first project: no-cost quotas cover a solo product for a long time, every deploy is a push, and each repo deploys on its own cadence.
2026-09-27 — Siblings, not a monorepo; the ops repo guards a canonical schema that every product repo copies byte for byte, checked in CI with a read token that fails the job when absent — repos sharing a data shape drift within a week, and a check that passes without running is the failure the check exists to prevent.
2026-09-27 — The generator does everything a session can (render, install, check, commit) and writes `HANDOFF.md` for the rest, each human step with its proof — the goal is minimum human action; the steps that remain are the ones a session has no way to do, and an undocumented manual step is a guess in prod.
2026-09-27 — Standard library only in `scripts/`: python3 for rendering and JSON, bash for checks — the harness already requires python3, and a generator that needs its own install step is one more thing to break before the first project exists.
2026-09-27 — Every spawned ops repo carries `.mainbrain/manifest.json` and a rule that structural changes ship to mainBrain in the same session — the skeleton must never be older than the best project, and a rule enforced by a tool (`upstream.py`) and a review beats a rule remembered.
2026-09-27 — The library holds one source per domain: `ui-ux-pro-max` for static UI, `animate` for motion with `review-animations` as its gate, `security-guidance` for security review — two advisors on one task produce two answers, and a second aesthetic across site and app is the visible symptom.
2026-09-27 — Plugins (`security-guidance`, `ui-ux-pro-max`) are enabled through the generated `settings.json`, not vendored — they ship their own hooks and data; vendoring would fork them.
2026-09-27 — This repo is public; examples use `example-owner` and `acme.example`, and spawned projects are never named here — the skeleton and the library are generic by construction, and keeping them public keeps the generic and the specific apart.
2026-09-27 — `repo_names` in the answers overrides `<project>-<kind>` for one repo, and the manifest records `repo_kinds` — a project that predates the generator cannot rename its repos, and the return path has to work for the first project too.
2026-09-27 — First upstream from the ancestor project: scroll-reveal that respects reduced motion in the site layout, footer legal constants, the green-deploy explanation, webhook-secret rotation, and three script comments — the skeleton was generalized from a project that kept improving; the return path exists so those improvements reach the next project.
2026-09-27 — Every ops repo carries `BRAND.md` at its root, a placeholder until the founder supplies it, and every CLAUDE.md sends a session there before it writes anything a user reads — a product's voice and copy rules are a document like the workflow, so one copy in ops read by path, not a copy per repo; the second project arrived with one and the skeleton had no place for it.
2026-09-27 — The architecture map pads to the longest repo name, and G1 says the Claude App cannot create repos on an organization either — a 24-character repo name ran into its description, and an organization install answered 403 without the Administration permission.
2026-09-27 — Repositories are created by a `workflow_dispatch` workflow holding a `REPO_ADMIN_TOKEN` secret, triggered by the session, never by a token in the session — a GitHub App on a personal account cannot create repositories and the session's proxy replaces any token it sends, so the only place a personal token can act is GitHub Actions; the workflow creates empty repos and nothing else, so the credential's reach stays one verb wide.
2026-09-27 — The create-repos workflow takes an `owner` input, empty meaning the token's account — the first real run created the repo under the user because `gh api user` is the token's owner, and a project whose repos live in an organization needs the target said out loud.
2026-09-27 — The create-repos workflow calls the REST endpoints (`user/repos`, `orgs/{org}/repos`) rather than `gh repo create` — the command goes through GraphQL, which refuses a fine-grained token on createRepository; the first organization run failed exactly there, after the organization's 366-day lifetime cap had already cost one run.
2026-09-27 — `HANDOFF.md` G1 describes the automatic path first and the manual one as fallback, and the setup page opens with the whole flow — the first spawned project waited on G1 as a human step while the workflow already existed; a procedure the session does itself has to read that way in the file the founder opens.
2026-09-27 — Firebase projects are provisioned by a workflow that authenticates through Workload Identity Federation and acts on one folder and one billing account, never by a session and never with a stored key — creating a project and linking billing is the one act that can create a bill; the identity's reach is one folder wide, its credential is a token minted per run, and a human approves every run.
2026-09-27 — Both provisioning workflows run in the `provisioning` GitHub environment with a required reviewer — the founder asked that repository and Google Cloud creation stay subject to approval; an environment gate is a click in the Actions UI, visible in the run, and it cannot be bypassed by the session that triggers the run.
2026-09-30 — The site's `CLAUDE.md` quotes taste-skill's anti-default list, and site and app forbid `ui-ux-pro-max --motion` — taste-skill stays out as a second static advisor, but its list of what a model draws with no brief costs six lines; ui-ux-pro-max's `--motion` dial attaches GSAP snippets, and the plugin does not know that `animate` owns motion, so the rule has to sit in the repos that call it.
2026-09-30 — `web-design-guidelines` joins the library as a merge gate on site and app, its rules vendored instead of fetched, and `pick-ui-library` as the app's library picker — nothing reviewed a UI diff for accessibility, focus and forms, and `animate` sent component work to a skill that was absent; the gate yields motion to `review-animations`, copy to `BRAND.md` and taste to `ui-ux-pro-max`, and every pick lands as a decision line before its install, so neither opens a second voice on a domain.
2026-10-01 — `playwright-cli` replaces `webapp-testing` for browser testing, pinned at 0.1.22 and installed by the setup script — site and app are Node projects and the Python skill needed a pip install and a script per check, while the CLI drives a page from the shell with element refs, screenshots, traces and request mocking; it runs in the web container once `open` gets the Chromium at `/opt/pw-browsers`, and two tools on one domain would split the habit, so the old one goes.
2026-10-07 — Plugins install from the Claude Code environment's setup script, rendered into HANDOFF E2 from the catalog, and `cloudflare@cloudflare` joins them for any front end with its API token held as a network secret (C3) — a cloud session never installs the plugins a repository's `settings.json` enables, so E3's "nothing to do" left `security-guidance` and `ui-ux-pro-max` absent from every session of the first project; the Cloudflare MCP server needs a bearer token because OAuth needs a browser, and a network secret keeps the token out of the session.
2026-10-07 — HANDOFF C3 and the ops Cloudflare section say Wrangler runs with a placeholder token and that `wrangler whoami` proves nothing — verified in a fresh session: the agent proxy replaces an `Authorization` header already present, and Cloudflare throttles Wrangler's token check (code 971) from the proxy's shared address while the same check by `curl` passes.
